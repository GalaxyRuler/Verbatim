# Desktop Audit Remediation Tracker

Last updated: 2026-06-28

This tracker turns the 2026-06-21 desktop audit into public, non-sensitive work
items. It intentionally avoids exploit instructions, private logs, transcripts,
recordings, API keys, and machine-local paths. Report sensitive security issues
privately using [SECURITY.md](../../SECURITY.md).

## Status Values

- `confirmed`: Current repository evidence shows the finding is valid.
- `partially-fixed`: Some remediation has landed, but the acceptance criteria are
  not fully met.
- `needs-manual-verification`: Static evidence is not enough; verify on the
  relevant packaged desktop app or operating-system runner.
- `deferred`: Valid work, but intentionally sequenced behind higher-risk fixes.

## Label Set

Use these labels for public issues derived from this tracker:

- Priority: `priority:p0`, `priority:p1`, `priority:p2`
- Area: `area:release`, `area:privacy`, `area:insertion`, `area:testing`,
  `area:tauri`, `area:onboarding`, `area:accessibility`, `area:dependencies`

## Milestones

- `0.9.x Hardening`: privacy disclosures, cancellation/insertion safety, release
  asset completeness, diagnostics visibility, and basic Tauri scope hardening.
- `0.10 Native Reliability`: native CI, packaged smoke tests, startup recovery,
  coordinator supervision, and first-run success checks.
- `1.0 Trust And Distribution`: signing/notarization, credential-store
  migration, SBOM/dependency policy, accessibility gates, and benchmark-backed
  platform guidance.

## Security Reporting Boundary

Public issues may discuss hardening outcomes and non-sensitive reproduction
steps. Do not publish exploit details, private transcripts, recordings, API
keys, provider credentials, full app-data directories, or unredacted logs.
